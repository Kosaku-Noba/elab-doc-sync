# v1.0への移行と復旧

## 変更される動作

- 同期モードは `each`（1ファイル＝1記事）のみです。`merge` を指定すると終了コード2で停止します。
- `pull` はローカル未編集の追跡済み文書を更新します。両側に変更があれば停止し、ローカルだけの編集は保持します。
- `status` はリモート本文・タイトル・添付一覧も取得します。通信できない状態を「最新」と表示しません。
- 同期失敗・競合・部分失敗は終了コード1、設定・引数不正は2、成功・変更なしは0です。
- リネーム＋本文編集を推測で紐付けません。`esync mv` で指定してください。
- `link` は除外状態も解除します。紐付け衝突とリモート取得失敗では変更しません。

## 更新前の確認

既存のMarkdown、画像・添付、`.elab-sync.yaml`、`.elab-sync-ids/` を保管してください。独自の `id_file` を指定した場合は、その親ディレクトリも対象です。設定ファイルにはAPIキーが含まれる場合があるので公開しないでください。

旧 `mapping.json` とハッシュ情報は読み込めます。旧共有mappingからターゲット別mappingへ移行するときはバックアップを作成します。`status`・`diff`・`--dry-run` は移行による書き込みを行いません。

```bash
esync status
esync diff
esync pull --dry-run
```

「基準情報なし」は、保存済み情報だけでは上書きの安全性を判断できない状態です。`diff` で内容を確認し、リモートを採用するなら `pull --force`、ローカルを採用するなら `push --force` を明示します。自動マージはありません。

## mergeを使っていた場合

既存の1記事を複数記事へ自動分割する移行は行いません。

1. 結合前の各文書を保管する。
2. 保持したい既存記事を、1つのMarkdownとして専用ディレクトリに用意する。
3. 設定を `mode: each` に変更し、新しい専用の `id_file`（例：`.elab-sync-ids/migrated/default.id`）を指定する。
4. `esync link <既存ID> --file <ファイル名> --target <ターゲット名またはdocs_dir>` で紐付ける。
5. `diff` と `status` で確認してから同期する。

各文書を独立した新規記事にする場合は、旧記事のIDを流用せず、新しい `docs_dir` と状態ディレクトリを用意してください。旧リモート記事は保持されます。

## リネームと追跡再開

```bash
esync mv docs/old.md docs/new.md --dry-run
esync mv docs/old.md docs/new.md
esync push

esync rm docs/note.md
esync link 42 --file note.md --target docs
```

`mv` のパスはカレントディレクトリ基準です。同じターゲット内の移動に対応し、リモートタイトルは次のpushで更新します。エディタ等ですでに移動済みでも、旧紐付けと新ファイルを指定できます。移動先が存在する、同名文書が重複する、同期が未完了といった場合は停止します。

自動リネームは旧本文ハッシュが一致し、対応先が一意な場合だけ行います。推測できないときは `mv`、削除と新規作成が別の操作なら旧文書の `rm` を使います。

## バックアップと復元

```bash
esync backup list
esync restore <バックアップID> --dry-run
esync restore <バックアップID>
```

ローカル変更前に `.elab-sync-backups/` へ文書・状態・設定された添付ディレクトリを保存します。**復元単位は一覧に表示されるディレクトリまたはファイル全体**です。保存時点に存在しなかったファイルも復元先から取り除かれるため、最初にdry-runで範囲を確認してください。復元直前の状態も新しいバックアップとして保存します。

- バックアップに失敗した場合、元の文書を変更しません。
- バックアップは自動削除しません。不要になった世代のディレクトリは、復旧不要と確認してから手動で削除できます。
- プロジェクト外のパスとシンボリックリンクはバックアップ・復元対象にできません。画像・動画・ファイルリンク・添付の送信もプロジェクト内に限定し、隠しファイル・隠しディレクトリ内の参照とシンボリックリンクを拒否します。実体をプロジェクト内の通常ディレクトリへ配置してください。
- `push --force` 前のリモート本文は、接続先・ID・タイトル・本文形式とともに退避します。`restore` すると `.elab-sync-backups/<ID>-remote.json` に取り出します。リモートには書き込みません。内容を確認してMarkdownに反映し、`diff` 後にpushしてください。
- `--prune-attachments` によるリモート添付削除は、リモート本文の退避からは戻せません。必要な添付を事前にローカルへ保存してください。

## 途中失敗の復旧

ローカル操作が中断した場合は `.elab-sync-recovery.json` に復旧用IDを記録します。表示された `restore <ID>` を実行してから再開します。OSが解放するロックを使うため、プロセス終了後にロックファイルを手動削除する必要はありません。

リモート本文・添付・メタデータの一部だけ成功した場合、未完了情報を保持します。通常のpushを再実行すると成功済み文書をスキップし、未完了の文書を再確認します。記録した状態以外のカテゴリ・タグ・添付変更がある場合は再開を停止します。自処理の変更か判別できない場合も、diffやサーバー画面で確認してから採用する側を指定してください。

記事の新規作成要求で応答が失われた場合は、自動再作成しません。

```bash
esync list --limit 100
# 作成された記事がある場合
esync link <ID> --file note.md --target docs
# サーバー側にも対応記事が存在しないと確認できた場合だけ
esync link --new --file note.md --target docs
```

一覧はサーバー側の表示件数に制限される場合があります。必要に応じてeLabFTWの画面でも確認してください。作成記録 `.elab-sync-operations/` はローカル復元の対象外とし、復元で紐付けが戻っても重複作成を防ぎます。

以下をGit管理対象外にしてください（新規init/cloneでは案内・生成します）。

```gitignore
.elab-sync.yaml
.elab-sync-ids/
.elab-sync-backups/
.elab-sync-operations/
.elab-sync-recovery.json
```

## 保証の範囲

リモートAPIには複数リクエストをまとめたトランザクションがないため、リモート更新・ローカル保存を完全に同時確定することはできません。失敗時の停止、退避、作成ID・未完了記録で復旧します。サーバー側で同時編集が発生する極短時間の競合まで排除するものではありません。

本文形式は [eLabFTW公式資料](https://doc.elabftw.net/docs/usage/import-export/) の `content_type`（1=HTML、2=Markdown）に従います。HTMLからMarkdownへの変換は表示内容の維持を対象とし、元のHTMLの完全再現は保証しません。
