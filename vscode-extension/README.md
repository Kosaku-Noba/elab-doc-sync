# esync for eLabFTW

VS Code の左端にある esync アイコンから、編集中の Markdown の送信先と、プロジェクト全体の同期状態を確認できます。

## セットアップ

1. elab-doc-sync のリポジトリ直下で `uv tool install --force .` を実行します。`esync --version` が 1.5.0 以降の版を使います。古い版や版を確認できない場合は、ワークスペースを開いたときに警告が表示されます。
2. VS Code 1.85 以降のコマンドパレットで「Extensions: Install from VSIX...」を選び、`esync-0.3.0.vsix` を開きます。ソースから使う場合は、先に下の「VSIX の作成」を実行し、`dist/` にできたファイルを選びます。
3. `.elab-sync.yaml` があるディレクトリをワークスペースフォルダーとして開きます。接続先や API キーは CLI と共通です。環境変数を使う場合は、VS Code の拡張ホストからも参照できるようにしてください。

信頼済みのファイルシステム上のワークスペースで、PATH 上の `esync` を使います。別の環境にインストールした場合は、VS Code のユーザー設定 `esync.executable` に実行ファイルの絶対パスを指定できます。リポジトリで `uv sync` 済みなら、その `.venv/bin/esync`（Windows は `.venv\Scripts\esync.exe`）も指定できます。

同期状態や差分の取得は、既定で 120 秒たつと打ち切ります。待ち時間は設定 `esync.timeoutSeconds` で変更でき、0 にすると打ち切りません。差分の取得中は通知の「キャンセル」で中止できます。push では、送信直前に差分を取り直して内容が変わっていないかを確かめます。この確認には同じ待ち時間が適用され、ここで時間切れになった場合はまだ何も送信していません。送信が始まった後は、記事を中途半端に更新しないよう、時間で打ち切らず、キャンセルもできません。CLI の警告やエラーは出力「esync」に記録されます。

## 使い方

- Markdown エディタ右上の「この文書の差分を確認」で、前回の同期からの変更を読み取り専用のタブに表示します。未保存の編集は、保存してから確認できます。
- 複数のターゲットに一致する文書は、送信先を選んで差分を開きます。差分タブには送信先と、新規作成か既存の記事 ID かが表示されます。右上の「この差分の文書を push」で送信します。本文・参照ファイル・設定などが変わった場合は差分を開き直してください。
- 送信先を区別できないと表示された場合は、`.elab-sync.yaml` でそのターゲットに一意の `title` を付け、差分を開き直してください。
- 左端のノート形の **esync** アイコンをクリックします。上の「開いている文書」には、選択中の Markdown の送信先ターゲット、記事 ID、保存した内容の同期状態が表示されます。「差分を確認」を押すと、その文書のプレビューが開きます。送信先が複数表示される文書は、目的のターゲットを展開して「差分を確認」を押します。改名した文書は差分タブの先頭で引き継ぐ記事 ID を確認できます。記事 ID がまだ記録されていない文書では、記事 ID 欄に次のどれかが表示されます。
  - 「確認中…」: 初めて照会している間か、改名元の候補（ローカルにない記事）が変わった後に照会し直している間です。候補が変わると、この文書が引き継ぐ記事 ID も変わる可能性があるので、前回の ID は表示しません。
  - `#42` のような記事 ID: 照会で、この文書が引き継ぐ記事 ID が判明すると表示します。候補が変わらなければ、照会し直している間もその ID を表示します。前回の push が途中で止まった「同期未完了」の文書では、改名していなくても、その push で作成した記事の ID を表示します。
  - 「未割り当て」: 送信先の記事 ID が決まっていない文書です。改名元の候補がなく、同期未完了でもない文書は、照会せずにこう表示します。候補があっても、照会の結果、引き継ぐ記事がないと判定された場合もこう表示します。未追跡の文書は、push すると新しい記事として作成されます。同期状態が「作成結果不明」の文書は、前回の push で記事が作成済みの可能性があり、このままでは再度 push しても作成をやり直せません。サイドバーの送信先で記事ができたかを確かめ、[途中失敗の復旧](https://github.com/Kosaku-Noba/elab-doc-sync/blob/main/docs/13_MIGRATION_V1.md#途中失敗の復旧)の手順で紐付けるか作成をやり直してください。
  - 「確認できません」: 照会に失敗したか、送信先を一つに絞れなかった場合です。既存の記事がある可能性があるので、併記されたエラーを読むか「差分を確認」で送信先を確かめてください。

  記事を取得できなかった場合も、判明した記事 ID はエラーと並べて表示します。
- 下の「プロジェクト全体の同期一覧」には「送信待ち」「取得待ち」「競合」などの状態ごとに文書が並びます。ローカルにある文書は、行をクリックすると編集でき、行にポインターを合わせて差分ボタンを押すとプレビューできます。
- 送信先サーバーは差分タブの先頭で確認できます。パネル右上の更新ボタンで最新の同期状態を取得できます。取得中は前回の一覧が表示されたままになります。一覧の更新に失敗した場合、エラーの下には前回取得した一覧が表示されます。本文を取り込むには CLI の `esync pull` を使います。Markdown の保存後と push の後にも一覧を更新します。

## 開発

Node.js 22 以降が必要です（テストに使う `@vscode/test-electron` の要件）。このディレクトリで `npm install` を実行してから、次のコマンドを使います。

- `npm run check`: JSDoc の型注釈を TypeScript で検査します。
- `npm test`: 拡張ホストでテストを実行します。VS Code を自動で取得します。インストール済みの VS Code を使う場合は、環境変数 `VSCODE_EXECUTABLE` に実行ファイルのパスを指定します。画面のない Linux では `xvfb-run -a npm test` で実行します。

## VSIX の作成

このディレクトリで次を実行します。

```sh
mkdir -p dist
npx --yes @vscode/vsce package --no-dependencies --out dist/esync-0.3.0.vsix
```
